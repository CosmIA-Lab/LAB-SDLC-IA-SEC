  • Vulnerabilidades em aplicações webconsequências previsíveis do modelo de execução, não lista de nomes
    • Fundamentos4 fatos do modeloum programa dividido por uma fronteira que o atacante controla
      • 1 · toda entrada é hostil
        • o navegador é opcionalcampo oculto, cabeçalho, cookie, Referer, nome de arquivo, método: tudo é escolha do cliente
        • validar no servidor, por lista de permissãovalidação no cliente é conveniência, nunca controle
      • 2 · dado e instrução compartilham o canal
        • SQL, HTML, shell, URL são textoo interpretador não sabe onde o dado termina
        • defesa = separar por construçãoparametrizar, codificar por contexto; nunca filtrar caracteresIEEE CSD 14 #4
      • 3 · a identidade é um token que viaja
        • HTTP sem estadocada requisição chega sozinha; o cookie diz quem é
        • token = senha temporáriaconfidencialidade · integridade · escopo · expiração
      • 4 · a web é composição sob a política de mesma origem
        • origem = esquema + host + portaNetscape 95; Barth RFC 6454 11
        • isola LEITURA, não ENVIOpor isso CSRF existe; CORS relaxa; cookies vão por host
        • toda vuln "entre sites" = política contornada, relaxada ou ausente
