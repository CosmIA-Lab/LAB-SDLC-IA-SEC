Cada estágio commita o que o próximo lê. O histórico vira trilha de auditoria.

Fase 1 · Requisitos ↔ Plan

O que o sistema deve garantir

Princípios
  • Verificabilidade
  • Rastreabilidade
  • Negação explícita
Técnicas
  • Abuse caseMcDermott e Fox, 1999
  • Misuse caseSindre e Opdahl, 2000
  • Attack treeSchneier, 1999
Mecanismo com IA
  • Intenção conversada com o agente
  • Template de intent.md pede requisito negativo e critério de aceite
Saída: requisito com teste. Sem teste, não entrou no ciclo.
Fase 2 · Design

Desenho seguro antes do código

Princípios
  • Least privilege
  • Defense in depth
  • Fail secure
  • Zero trust
Técnicas
  • Modelagem de ameaçasShostack, 2014
  • DFDDeMarco, 1979
  • Superfície de ataqueManadhata e Wing, 2004
Mecanismo com IA
  • spec.md gerada sob skill de segurança
  • Conflito com política vai para o dono decidir
Saída: desenho com ameaças e mitigações. Sem mitigação, não saiu da fase.
Fase 3 · Código ↔ Build

Sem repetir falha conhecida

Princípios
  • Never trust input
  • Nada hard coded
  • Identidade e sessão não se improvisam
Técnicas
  • Inspeção formalFagan, 1976
  • Secure code reviewOWASP Code Review Guide
  • SAST no commitver ponto 7
Mecanismo com IA
  • Modo plano: lê sem editar → plan.md
  • Hook bloqueia segredo no diff e caminho protegido
Saída: código revisado, com teste que prova o requisito.
Fase 4 · Testes ↔ Test

Achado com evidência

Princípios
  • Achado sem prova não é achado
  • Bug bar decide a release
  • Testar os sete alvos, não só o fonte
Técnicas
  • FuzzingMiller et al., 1990
  • SAST · DAST · SCAver ponto 7
  • Pentest
Mecanismo com IA
  • Teste que falha primeiro, protegido contra edição
  • Todo incidente vira eval permanente no CI
Saída: achado com severidade, prova e decisão.
Fase 5 · Deploy e manutenção ↔ Deploy + Maintain

Detectar e responder em produção

Princípios
  • Assume breach
  • Log sem segredo
  • Alerta sem resposta não existe
Técnicas
  • Resposta a incidentesNIST SP 800-61
  • Gestão de vulnerabilidadesver ponto 10
Mecanismo com IA
  • Agente vai até o portão de produção; uma pessoa nomeada passa
  • 1σ registra · 2σ diagnostica · 3σ propõe PR
Saída: incidente contido e lição virando intent.md.
O agente também é superfície de ataque

Os princípios da Janca aplicados ao agente

PrincípioGuardrail no agente
Least privilegePermissão mínima, token de CI curto e escopado
Sem segredo em códigoLeitura de .env e credenciais negada
Zero trust + fail secureSandbox com allowlist de domínio que falha fechado
Ameaça internaQuem escreveu o código não aprova; sem rota direta para a main
Cadeia de suprimentosSó hooks, plugins e MCP gerenciados
Segurança usável

Aconselhar não é impedir

ControleMecanismoEfeito
AdvisorySkill, CLAUDE.mdConformidade provável
EnforcedHook, permissão, branch protectionViolação quase impossível

Controle que atrapalha é contornado (Janca).
Por isso a regra que sempre vale fica no sistema, não no hábito.
