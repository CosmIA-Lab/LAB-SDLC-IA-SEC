SDLC-SEC

CUSTO cresce com o tempo

curva de Boehm, 1981 — é o fundamento de tudo

PUSH LEFT — empurrar p/ esquerda

estratégia, não princípio (Janca, 2020): decide quando aplicar os princípios

FALHA ≠ BUG

falha = erro de desenho → corrige com reprojeto

bug = erro de implementação → corrige com patch

age cedo em TODO o ciclo → o que vale ANTES de qualquer fase?

FUNDAMENTOS — 12 conceitos de base

valem no ciclo inteiro; por isso vêm antes das fases

CIA · assume breach · ameaça interna · defense in depth

least privilege · cadeia de suprimentos · sem obscuridade

superfície de ataque · sem segredo no código · zero trust

segurança usável · fatores de autenticação

fixada a base, qual é o ciclo?

1 · REQUISITOS

o que o sistema deve garantir

Pverificável · rastreável · negação explícita

Tabuse case (McDermott/Fox 99) · misuse (Sindre/Opdahl 00) · attack tree (Schneier 99) · bug bar (MS SDL)

→ requisito com teste

2 · DESIGN

desenho seguro antes do código — fase mais barata; aqui nasce a FALHA

Pleast privilege · defense in depth · fail secure · zero trust

Tmodelagem de ameaças (Shostack 2014, 4 perguntas) · DFD (DeMarco 79) · superfície (Manadhata/Wing 04)

→ desenho com mitigações

3 · CÓDIGO

código sem falha conhecida

Pnever trust input · nada hard coded · bounds checking · erro não ajuda o atacante

Tinspeção de Fagan (76) · secure code review (OWASP) · SAST no commit

→ código revisado + teste

4 · TESTES

falha encontrada com evidência — 7 alvos: código·app·infra·BD·APIs·integrações·rede

Pevidência · severidade (bug bar) · cobertura dos 7 alvos

TSAST · DAST · SCA · fuzzing · secret scanning · pentest

→ achado com severidade + prova + decisão

5 · DEPLOY + MANUTENÇÃO

detectar e responder em produção

Passume breach · log sem segredo · detecção vale a resposta

Tresposta a incidentes (NIST 800-61) · gestão de vulnerabilidades

→ incidente contido → vira requisito do próximo ciclo

extra · DESCONTINUAÇÃO

encerrar sem vazar (MS SDL / NIST SSDF) — só checklist, sem técnica nomeada

processo escrito ≠ processo executado → como garantir SEMPRE?

DEVSECOPS — Dev + Sec + Ops

responsabilidade compartilhada, automatizada, contínua

SHIFT-LEFT + SHIFT-RIGHT

shift-left = push left por commit · shift-right = monitorar produção

previne × detecta — um sem o outro deixa buraco

PIPELINE CI/CD

commit → build → testes → análise (SAST/SCA/secrets) → staging → DAST → prod

regra de ouro: verificação falha → pipeline PARA

FERRAMENTAS

SAST (Semgrep) · DAST (ZAP) · SCA (Trivy) · secrets (gitleaks) · fuzzing

WAF / RASP — compram tempo, não corrigem

SDLC ≠ DevSecOps

processo (o quê) × prática (como, em escala)
